## [Unreleased]

### Fixed

- Native Grok Bot skill tests fold `>-` descriptions in process, so CI no longer needs PyYAML. The label-safety cwd check compares canonical paths, which is what macOS `getcwd` returns for `/var`.
- Grok Bot tracking commands load configuration from the supplied environment, so isolated callers honor their tracking settings instead of the operator's configuration.
- Doctor recognizes optional service backends, diagnoses the effective value from preceding config layers, checks the selected gateway credential without requiring unused direct credentials, and reports loose control files and stale state-root remnants.
- Review scans reject malformed pagination metadata and author classification, enforce one deadline across repository lookup and every page, and cannot authorize a fresh review when the thread scan fails.
- Doctor removes URL credentials from effective-value reports and explains model selectors containing control characters; its credential guide names the actual Substrate backend and off switch. Pruning preserves the strict `last.json` lock of a live writer regardless of age. An unreadable thread scan returns `unverified`, keeps a completed Greptile review reusable, and does not consume review retries or rounds.
- Stale-lock recovery, acquisition, release and pruning serialize lock-name mutations through an ownership-safe guard. A delayed recovery no longer moves a live successor aside or loses a session update. The strict last-mirror policy remains fail closed; generic session/control timeouts remain fail open.
- Completed last-mirror writers mark their own opened inode inactive before guarded removal, so temporary guard contention cannot strand a live host PID. Retention removes old prepared guard directories only for dead owners, preserving live and unrelated contents. The controlled stale-recovery regression forces the empty-guard successor handoff and observes failed late removal too; its exact-counter and no-overlap checks reject any unlocked fallback.
- The stale-recovery process fixture receives explicit synchronous pipe messages rather than treating filesystem notifications as barriers. Timeouts identify the blocked barrier; exact updates, no critical-section overlap and no unlocked fallback remain required.
- Desk gateway recall keeps string metadata and applies the caller's tag filter; a per-bank `not_configured` fails the health check; unsupported document updates are not reported as a missing document. Document search drops chunks under `similarityThreshold`. An invalid `DESK_GATEWAY_SEAT` keeps the configured seat. RAGFlow's gateway check reports a probe, not a dataset count. Teachable Moments loads the gateway section. A one-prompt skip is consumed by `plan`. Graph-free plans are valid when thinking is off. `track payloads` honors tracking off, skips rows that already exist, and a single configured tracker can finish. `answers` and `track record` refresh `last.json`. Cloud-prompt placeholder checks ignore the verbatim original. Review read uses the current head's score, then the newest comment or review by time, and follows GitHub pagination. Teach digests keep every line of a mixed transcript, skip hidden Claude entries, name tool results from `tool_use_id`, and keep an interrupted outcome. `track payloads --out` writes an empty payload when tracking is off. `last.json` writers share one lock, and each replace uses its own temp file. A lock left by a dead process is reclaimed immediately. A fresh empty lock stays held. If a live process still holds it, the session and spec stay available and the plan says `ctl last` was not refreshed.

### Added

- Native Omp dashboard. `/ultrathink-ui [overview|jev|moments|skills|card]` opens a keyboard-driven native dashboard (Overview, Jev, Moments, Skills panels) over the current session's latest saved Jev decisions and the current project's lessons, with explicit candidate confirmation, deterministic draft preview and separately confirmed Omp install through the existing teaching commands and installer guards; `card` publishes a bounded captured summary card labeled `captured — not live`. Browsing/refresh/preview are passive and local; guarded actions need the Omp TUI and are refused in subagent sessions, with the UI disabled, or outside the TUI. Retain acknowledgments are version-bound so a mid-flight capture cannot be marked synced; Esc during a dispatched action reports honestly that it cannot be stopped; detail, preview and Overview content wraps and scrolls within the real viewport, Skills shares one scroll budget between its settings and lesson list, list navigation stays available on narrow terminals, and compact cards always lead with lesson lifecycle counts. No browser, React, runtime dependency, model/provider loop or teaching-policy change. See [Commands](docs/commands.md#omp).
- Native Omp insight readability and focus. Lesson/draft whitespace and full bounded provenance survive wrapping and scrolling; affected panels disclose partial reads, policy-off actions stay unavailable, and layout-only refusals clear after resize. Expanded captured cards reflow recorded decision metadata within a 24-row physical budget, preserve policy/read-limit space and disclose capture/detail omissions. Opening shows local loading feedback, and returning from preview or closing preserves selected details and the composer draft.
- Native Omp action receipts preserve the complete bounded destination and promotion time. Busy controls identify the pending operation rather than a false terminal-size failure, and populated Overview distinguishes the saved Jev threshold from current promotion policy and qualifies latest-plan scope.

- Cursor pstack bridge. A `beforeSubmitPrompt` hook detects a `/gsd-*` command at the start of a line — a quoted example (including one that spans lines), an inch mark such as `12"`, or a mention later in a sentence is not an invocation — and injects local instructions to read the mapped pstack skills (`how`, `architect`, `arena`, `tdd`, `interrogate`, `no-comments`) by absolute `SKILL.md` path. Off unless `pstack.enabled` is true in the user config the hook reads; a project file cannot enable it, and `ULTRATHINK_PSTACK=0` forces it off. `bun scripts/cursor-hooks.ts install` and `remove` own one `ultrathink-managed` entry and never touch `gsd-managed`, `substrate-managed` or other entries. The installer stores a shell-quoted command under an absolute Cursor directory, it will not replace `hooks.json` when that file changes while the write is in progress, and it will not stage the hook when `hooks.json` parses but has the wrong shape. `install` and `remove` hold one lock across the staged-file snapshot, the copy, registration and restore, so a failed install cannot roll back a hook another install already registered. A dead holder's lock is reclaimed; a fresh empty lock is left alone. `ultrathink doctor` reports the deciding file, the resolved plugin, each stage's skills and whether the hook is installed; it follows the same off switch and the same first-parsed-file rule as the hook, and a missing skill is a warning only while the bridge is enabled. See [Run pstack skills beside GSD in Cursor](docs/how-to/use-pstack-with-cursor.md).
- Opt-in desk gateway backend for Hindsight, RAGFlow and the substrate brief. `hindsight.backend`, `ragflow.backend` and `substrate.backend` stay `direct` unless set to `gateway`. A `gateway` section (`url`, `seat`, `timeoutMs`) plus `DESK_GATEWAY_TOKEN` or a stored `desk-gateway` credential calls `desk_memory_recall`, `desk_memory_retain`, `desk_docs_search`, `desk_brief` and `desk_event_emit` on `<url>/mcp/<seat>`. No Hindsight or RAGFlow key is read on that path. `ULTRATHINK_GATEWAY=0` forces the direct clients. Status lines report `gateway · ready` or `gateway · unready` with the reason.
- Grok Bot native host. `bin/ultrathink-grokbot` runs `planPrompt` with a journal completer: every completion the engine needs is written to `<stateDir>/journal/<session>/pending/`, the bot answers it by following the plugin's own system prompt, `answer` validates it the way the engine parses it, and the next `plan` replays it. Jev decisions are journalled for resumed runs. Shipping is forced off. `track payloads` / `track record` bridge `createTracking` to the bot's Linear and Notion connectors; `answers` folds chat replies into clarifications (the AskUserQuestion hook's job); `teach digest` builds a `TeachDigest` from the bot's turns for `teach observe` (the Stop hook's job); `prompts build` derives validated cloud-agent prompts per node; `review read` reads the Greptile score and threads; `skills status` reports drift between the 21 staged skills in `hosts/grok-bot/skills` and the installed copies. `ultrathink.discovery.json` lists `grok-bot` with status `native-adapter`, delivery `skill-protocol-cli`, `adapterPresent` true and `compatibilityVerified` false. See [Use with Grok Bot](docs/how-to/use-with-grok-bot.md).
- `ultrathink doctor` checks config files, credentials, the state directory and the runtime without a network call. Unknown keys get a suggestion, ignored or adjusted values are named with the effective value, and `--json` prints a stable report. Exit 1 only when an error finding exists. See [Diagnose with doctor](docs/how-to/diagnose-with-doctor.md).
- `ultrathink prune` removes session records older than a cutoff, with `--dry-run` and a refusal below one day. `state.retentionDays` (user config only, default 0) opts into the same prune at most once a day from the plan path. An active ship and the carrier session are never removed, and prompt text is never printed. See [Session retention](docs/configuration.md#state-session-retention).
- A tag `vX.Y.Z` runs `.github/workflows/release.yml`, which re-runs the gates, checks the tag against every manifest and `CHANGELOG.md`, and opens a GitHub release from that changelog section. It does not publish to a package registry. `bun scripts/release-check.ts` is what the test suite runs so a drifting version cannot merge.

### Changed

- Omp command help and privacy notes now cover `/ultrathink-ui`: panel meanings, keyboard/focus/refresh/close behavior, compact/expanded captured cards, latest-saved-plan (not complete-history) Jev scope, deterministic eligibility and recorded-promotion limits, and the passive-local browsing versus explicit-confirmation/install data flow. No behavior change.

- Review threads are read page by page (100 at a time, at most 2,000). A pull request with more than 100 threads no longer fails the ship gate closed; a page that cannot be read, a bad or repeated cursor, or a 21st page still does.
- Session, control, last, carrier and spec files are written atomically with mode `0600` in `0700` directories. Grok Bot answers and tracker-reference updates use the same session lock and private atomic writes. Session and control read-modify-write locks fall back to an unlocked write on timeout instead of blocking the prompt. `last.json` keeps its strict PID lock, including live holders older than the stale-empty threshold: a busy lock saves the session, leaves the previous mirror intact, and returns a warning.
- CI cancels a superseded pull-request run, bounds each job, checks out without persisting credentials, and pins every action to a commit SHA. Dependabot updates GitHub Actions and Bun weekly. CodeQL scans JavaScript/TypeScript and Python on every pull request, including forks, on `main` and weekly.
- The Prime Agent bridge test ignores `ULTRATHINK_STATE_DIR` and other host variables from the shell that launches it.
- `tsconfig.json` enables `noImplicitOverride`, `noFallthroughCasesInSwitch`, `noImplicitReturns`, `noUncheckedSideEffectImports`, `noUnusedLocals`, `noUnusedParameters` and `noUncheckedIndexedAccess`.

## [1.4.0] - 2026-10-08

### Added

- Prime Agent host. `hosts/prime-agent` is a Python-backed Prime Agent skill: the kernel loads it as `ultrathink`, and `await ultrathink("<request>")` plans through `hooks/engine.ts` with the host `prime-agent`, the Prime Agent session id and the kernel's working directory, returning the plan (`context`, `spec`, `spec_path`, `state_path`, `graph_id`, `summary`, `view`, `model_resolution`) to the kernel. `ultrathink.ctl(...)` runs the `/ultrathink-*` controls, `status()`, `last()`, `spec()` and `teach(...)` read state and Teachable Moments. State lives in `${PRIME_AGENT_CODING_AGENT_DIR:-~/.prime/agent}/ultrathink`; `detectHost` recognises the kernel's `PRIME_AGENT_CODING_AGENT_DIR` / `RLM_SESSION_DIR`; the Claude route is the default engine; `/skill:<name>` resolves project and personal Prime Agent skills; Teachable Moments gain the `prime-agent` promotion target (`~/.prime/agent/skills/<name>/SKILL.md`). `bun scripts/setup.ts apply` links the host into the Prime Agent skill directory and the `ultrathink-*` skills into `~/.agents/skills`; `status` and `rollback` cover them. The discovery descriptor lists the host with the delivery `kernel-skill-return`. Tests: `python3 hosts/prime-agent/bridge_test.py`. The six `/ultrathink-*` control commands are also Prime Agent skills (`hosts/prime-agent/commands/<name>/SKILL.md`, linked into `~/.agents/skills` by `apply`), carried out through `ultrathink.ctl(...)`.
- Agent Substrate: a planned prompt now reports itself to the substrate. With `substrate.url` or `SUBSTRATE_URL` set, `runPromptSubmit` sends one `note` event (`POST <url>/events`) once the plan's session record is written, on every host. It carries the Graph ID as `graph_id`, the session id `<host session id>:<Graph ID>` (so each planned graph gets its own chain), the host as `surface`, the repository and branch, the summary `ultrathink planned graph <graphId> (<n> nodes)`, and the payload `{ ultrathink: "plan", nodes, host }` plus `skill` (the skill's name) when a skill was invoked; the substrate adopts the Graph ID unchanged as its correlation key. No text of the prompt, the spec or the plan is sent, and nothing is sent for a prompt that is not planned, a fallback spec (no Graph ID), a session without an id or a record that could not be written. The request follows the brief's rules: no URL or `SUBSTRATE_DISABLED=1` means no request, `SUBSTRATE_TOKEN` is the bearer token, it times out after 1.5 s (`SUBSTRATE_TIMEOUT_MS`), and a refusal, a timeout or an error changes nothing the prompt gets. Registering the graph stays the `ultrathink-kickoff` skill's `graph_register` step.
- Plans recall promoted skills, not just lessons. The planner matches the prompt against promoted moments and the drafts under `<stateDir>/teach/skill-drafts/` (where Hermes and Muse skills live, since those hosts never install) and adds a `## Relevant skills` section after the documents: one line per skill with its trigger and `SKILL.md` path, never the skill body. A draft counts only while every lesson it was made from is still live, and only in those lessons' projects; the lookup reads a bounded set of the newest lessons and drafts and stops when the planning budget runs out. The session record keeps a `skills` lookup (outcome, count, names) and the summary gains a `Skills · <n> recalled` bit; on Hermes the pointers are the first evidence dropped when the handoff runs out of room. The orchestration step tells the agent to pass the lessons and skills that apply to each unit into the subagents it dispatches, so autonomous runs see them.
- A `models` config section: `models.hosts.<host>.model` and `models.hosts.<host>.provider` choose the planning model per host, and `models.providerDefaults.<provider>` names Omp's default model for one exact provider. It layers like every other key; a blank value clears an earlier one, an absent or wrong-type value keeps it, and the merge skips `__proto__`, `constructor` and `prototype`. See [Configuration](docs/configuration.md#models-planning-model-selection).
- Every planning selection now records one of four states, `detected`, `default`, `override` or `unresolved`, with its source and reason, as a safe label such as `claude:sonnet [route default]` or `omp-native:<provider>/<model> [detected]`. It appears in the summary line, a new `Planning model:` line in the plan context, the session record, `bin/ultrathink status` (`Last planned resolution:`) and, on Omp, the status bar, the plan cards and `/ultrathink-status`. It never holds an endpoint, a header or a credential. See [Planning model states](docs/how-to/choose-engine.md#planning-model-states).
- `ultrathink.discovery.json` and its schema `ultrathink.discovery.schema.json` at the repository root: a static, local description of the plugin for cross-agent discovery, listing the existing adapters for Claude Code, Grok Build, Hermes Agent, Muse, Omp and Prime Agent under the loader name `ultrathink`. Grok Bot and GPT Dot are listed as pending, with compatibility unverified. It is not a bot adapter or a planning server. See [Cross-agent discovery](README.md#cross-agent-discovery).
- `hooks/engine.ts` accepts an optional `provider` string. A request whose `host` is not a supported host, such as a bot name, is answered `unresolved` with reason `unsupported-host` and empty context instead of being planned as another host.

### Changed

- Teachable Moments are on by default: `teach.enabled` and `teach.autoPromote` now default to `true` and `teach.capture` to `"auto"`, so finished turns are distilled into lessons, matching lessons and skills are recalled into every planned prompt, and recurring lessons are installed as skills without a human step. This is not local-only: on every host, each qualifying finished turn (at least `teach.observeMinToolCalls` tool calls, default 4, plus a recovery, a user correction or a failed run) sends one extra call to the host's planning engine with a redacted excerpt of the session, tool calls and tool results included (at most 60 turns, 1 500 characters each, 24 000 in total). Recall, lesson files, drafts and skill installs stay on the local machine unless Hindsight is configured, and a project file can still only turn the feature off or lower it. `"teach": { "capture": "explicit" }` stops the distillation call. To keep the old behaviour, set `"teach": { "enabled": false }` (or `"capture": "explicit", "autoPromote": false` to keep manual capture with recall). See [Privacy](docs/privacy.md#planning-engine-lesson-distillation).
- Omp plans on the session's own model. With `think.engine: "auto"`, the Omp extension copies the session's live model once per prompt and runs the uplift, the graph, every node fill and the clarifying questions on it inside Omp, through Omp's own provider and login: no `claude` CLI login is needed and no credential is copied. When the live model can't be used, the provider's default from `models.providerDefaults` or Omp's installed catalog is used; when nothing can be used, the prompt goes through unplanned with the reason. A named engine opts Omp out and plans on that engine's CLI route. On reasoning-heavy models a native plan can take several minutes: after 25 s the agent gets the pending note and the plan arrives later as an aside. Each plan has its own 10-minute limit and is cancelled, never delivered, by a newer prompt, `/ultrathink-quick`, an observed model switch, a session switch or the end of the session (so a print-mode `omp -p` run that exits early gets no plan). The ship done check and the Teachable Moments distiller stay on the Claude CLI route under `auto`. To keep planning Omp prompts on Claude, run `ULTRATHINK_HOST=omp bin/ultrathink grok engine claude`. See [Choose the planning engine](docs/how-to/choose-engine.md#omp-the-sessions-own-model).
- Native Omp planning inherits the session's thinking level once for all stages, including its `off` convention, without silently lowering effort or changing the 25-second inline/600-second outer limits. Reentry notices thinking-level and effective named-route/provenance changes; the outer deadline releases a terminal no-plan result even when a provider ignores cancellation.
- The built-in planning models of the CLI routes now live in one version-controlled map, `ROUTE_DEFAULT_MODELS` in `src/route-defaults.ts` (`claude`: `sonnet`, `grok`: `grok-4.7`, `muse`: `muse-spark-1.3-contributor`). The effective defaults are unchanged, and each entry can be updated without touching the resolution logic. Native Omp planning never reads it. See [Route defaults](docs/configuration.md#route-defaults).
- Grok no longer hands a prompt to Claude on its own. On Grok Build under `auto`, a missing or expired Grok login used to plan on Claude; it now skips like a named Grok engine does. Claude replaces a selected Grok route only through the two explicit, labeled user switches: `grok.fallbackToClaude: true` (HTTP/CLI login missing or expired) and `grok.enabled: false` (documented ‘forces Claude even when Grok is selected’). Without them, a missing or expired Grok login skips planning with the unchanged `GROK_LOGIN_REQUIRED` notice. Naming `think.engine: "claude"` is a deliberate engine choice, not a replacement. The same applies to the ship done check and the Teachable Moments distiller. To keep the old behaviour, set `grok.fallbackToClaude: true`.
- `bin/ultrathink status` and `/ultrathink-status` replace the `Model: <claude.model> · concurrency <n>` line with `Engine request: <engine> (<config or control>[, native opt-out]) · concurrency <n>`, and add `Last planned resolution:` after a plan. On Omp without an observed plan the `Engine:` line reads `omp-native:auto (live model not observed)` instead of a guessed Claude model.
- Caller or provider cancellation aborts sibling planning work: no further engine call, tracker request, state write or plan delivery starts, and the host result is `skipped: "aborted"`. `claude.budgetMs` is separate: when that budget alone runs out, the plan built so far can still be delivered. Public engine and status labels project unsafe selectors without changing their wire values.

### Removed

- Omp's session-file model reader and its subprocess planner. The Omp extension no longer reads the last `model_change` entry of the session file, no longer starts `hooks/engine.ts` for a plan, and no longer maps the session model to a Claude, Grok or Muse family, so a GPT or other non-Claude session no longer plans on Claude `sonnet`. `hooks/engine.ts` stays the JSON entry for Hermes and other callers; called with `host: "omp"`, it now answers `unresolved` with reason `native-unavailable`.

### Fixed

- `hooks/engine.ts` waits for its response line to reach the pipe before exiting. Under Bun, `process.stdout.write` followed by `process.exit` (even from the write callback) drops everything past the 128 KiB pipe buffer, so a full plan response (context plus view) reached the Hermes and Prime Agent callers truncated and was read as no plan at all.

- Hermes plans with the engine of the session's model family again. The host-neutral plan entry dropped the `model` field Hermes sends, so `think.engine: "auto"` always fell back to the Claude host default — on a Muse session with Claude out of credits every plan was the 5-node boilerplate graph with one-question fills and no tracker rows. The entry now forwards `model` to engine selection, which uses it to pick the Claude, Grok or Muse route. Omp no longer plans through this entry; it plans on the session's own model (see **Changed**).

- Omp named-Grok reentry now notices effective endpoint changes, including a newly configured gateway after a settled skip. Existing agent/turn/tool lifecycle observations cancel changed-model flights before deferred work can write trackers, state or carriers; unchanged deferred plans survive turn-end events.

- Post-selection skips and errors retain their safe model-resolution record. Plan views also sanitize legacy saved engine labels, and record construction and rendering share one identifier-safety rule.

- An explicitly stored control engine of `auto` takes precedence over `think.engine`; the engine-choice guide now distinguishes that choice from an absent control value.

- Model-selection merging ignores inherited host provider/model fields and preserves lower own pins. Nonblank legacy model and shunt-alias controls are rejected before trimming or auth, without changing whitespace-only clearing or Grok lower-pin retention. Literal shell punctuation still reaches the selected CLI/body as data.

- Omp shunt-alias reentry now preserves control-invalid identity, so a valid-to-invalid change cannot reuse an old plan and invalid-to-valid recovery cannot reuse a skipped flight. Paused shared-pipeline test fixtures explicitly disable Decisions and isolate every credential lookup root instead of relying on the ignored `decisions.enabled` field.

## [0.4.0] - 2026-10-04

A fresh install now contacts only the services you configured, the installers work from any clone on Linux and macOS (Windows through WSL), and the documentation is written for people outside the project. Several defaults changed; every entry under **Changed** and **Removed** says how to keep the old behaviour.

### Added

- Hermes: the plugin registers `ultrathink-kickoff`, `ultrathink-sync`, `ultrathink-plan` and `ultrathink-ship` as Hermes plugin skills (`skill_view name="ultrathink:<name>"`), and the plan's kickoff and ship instructions give each skill's load call and absolute `SKILL.md` path, since Hermes does not list plugin skills to the model.
- `ultrathink-mcp session mark --state <file> <kicked-off|synced>` sets `kickedOff` or `synced` in a session record. `ultrathink-kickoff` runs it with `kicked-off` as its last step.
- Hermes: an end-of-turn sync nudge. Through Hermes' `pre_verify` hook, once per plan (per session and Graph ID), a coding turn (one that edited files with `write_file` or `patch`) that is about to finish with a tracked plan not yet synced is continued with an instruction to run `ultrathink-sync` (with the state file, Graph ID and, when the session opened one, the PR URL). The PR-creation nudge now names the Graph ID and the skill's load call and `SKILL.md` path too.
- `substrate.url` config key for the optional Agent Substrate brief. `SUBSTRATE_URL` still wins over it, and `SUBSTRATE_DISABLED=1` still turns both off.
- `ship.greptileOrganization` config key: the Greptile organization id or handle passed on every Greptile MCP call. An account in several organizations needs it; without it, `review` now returns `status: "blocked"` with a reason that names the key and the candidate organizations.
- `ultrathink-mcp auth login --tailscale` and `ULTRATHINK_OAUTH_TAILSCALE=1`: on a remote session, receive the OAuth callback through `tailscale serve`.
- `scripts/mcp-register.ts --replace` (also overwrite same-named MCP entries that are not ultrathink's) and `--remove` (delete only ultrathink's entries). `mcp-register` also warns when it is run from a plugin cache directory that the next plugin update replaces.
- `bin/ultrathink status` (and `/ultrathink-status`) shows a `Substrate:` line (off, or the URL and whether it came from `SUBSTRATE_URL` or the config) and a `Ship:` line (off, or on with the auto-merge and delete-branch settings).
- Ship: `bin/ultrathink-ship review` returns `status: "blocked"` before any review round when Greptile is not set up (the `greptile` CLI is missing or signed out and no Greptile credential is stored), with the setup commands. A failed or slow `greptile whoami` is not treated as "not set up".
- Ship: `gsd-tools.cjs` is found in the standard GSD install locations (project, including the legacy project-local `.claude/get-shit-done`, `CLAUDE_CONFIG_DIR`, `~/.claude`, `~/.agents`, Hermes, Codex, Gemini, Cursor, opencode, and the legacy `~/.claude/get-shit-done`); `GSD_TOOLS` still wins. It runs with `node`. A GSD roadmap whose tools cannot be found, or whose tools cannot run because `node` is not on `PATH`, is reported as its own assessment gap instead of silently reading as zero phases.
- Hermes: when Hermes does not report its plugin hook cap, the plugin reads `plugins.hook_callback_timeout` from the active Hermes profile's `config.yaml` (`${HERMES_HOME:-~/.hermes}/config.yaml`, or `profiles/<name>/config.yaml` when a profile is active), with Hermes' own rules (negative → 30, over 600 → 600, 0 = no cap), else assumes Hermes' 30 s default, and logs one warning naming `hermes config set plugins.hook_callback_timeout 600`.
- Hermes: when `hooks/engine.ts` or `bin/run-bun` is not beside the plugin (for example, `hosts/hermes` was copied instead of symlinked), Bun is not started and one warning says to install `hosts/hermes` as a symlink into a full clone.
- `package.json` declares `engines.bun >=1.2`. CI runs Bun 1.2.x and the latest Bun on Linux and macOS, and the Hermes plugin tests on Python 3.10, the minimum the plugin now states.
- Documentation for new users: a documentation index (`docs/README.md`), a getting-started tutorial, task guides in `docs/how-to/` (Notion, Linear, the MCP gateway, engine choice, ship with Greptile, cost and latency, headless and CI, team and project config, upgrading and moving, uninstalling), a privacy page listing what leaves your machine, and an FAQ. The configuration and command references now cover every config key, environment variable, flag and exit code.
- `hitl.knowledgeBase` config key (opt-in, default `false`): before the clarifying questions, the planner reads the repository's Greptile knowledge base through the stored Greptile credential (found by the git remote's `owner/repo`; `index.md` plus up to 3 matching documents, at most 24,000 characters, 20 seconds per stage) and gives it to the clarifier as untrusted evidence. Questions it settles are not asked: they appear under "Answered" as `(Greptile knowledge base: <document>)` and in the spec as `<ANSWER source="knowledge" evidence="…">`, and are not carried to the next prompt. Only list and read calls go to Greptile; nothing from the prompt or the code is sent. Every lookup is surfaced (summary `Knowledge · 3 docs · 1 settled`, `none`, `off (no Greptile login)` or `error`; the session record's `knowledge` field; a `## Greptile knowledge base` context section; a `ULTRATHINK_DEBUG=1` log line; an Omp status-bar `kb` segment), and any failure falls back to the questions you would get with the key off. `ship.greptileOrganization` is sent as the organization when set.
- `bin/ultrathink status` (and `/ultrathink-status`) shows a `Knowledge base:` line: off, not read while HITL is off, no Greptile credential, or on with the Greptile organization in use.
- Ship: `ship.reviewRetries` config key (integer >= 0, default 3): a failed Greptile review (Greptile FAILED/ERROR/SKIPPED, no score, CLI failure) or one pending past `ship.reviewTimeoutMs` is re-triggered on the next `review` call, up to this many times per head commit; then the ship blocks with a PR comment.
- Ship: `ship.mergeTimeoutMs` config key (integer >= 1 ms, default 3600000 = 60 min): how long `merge` keeps retrying one reviewed head commit before the ship blocks.
- Ship: `ship.attempts` in the session record: every review result and merge outcome (newest 50), shown by `bin/ultrathink-ship status` and, as the last 10, in the `ultrathink-ship stopped` PR comment.
- Ship: `ship.judge` config key, `"gate"` (default, unchanged behaviour) or `"advisory"`. In advisory mode only the deterministic rules decide whether the task is done, so the agent always opens the PR itself once they pass; the LLM judge's verdict (or its error) is recorded under `judge` in the assessment and shown in the PR body, and never blocks. The merge gate (Greptile score >= `ship.minScore` with no open threads, CI) is the same in both modes.
- Ship: several PRs per session, one after another. `assess` in another repository or branch archives a finished (`merged` or `blocked`) ship into `ship.history` (last 10) and starts a fresh one, and refuses while the previous ship is still active. A merged ship is archived even on its own branch, and a failed archive write stops `assess`. `pr` records the PR's `owner/repo` as `pr.repo`.
- Jev decisions (always on once a key exists; `ULTRATHINK_DECISIONS=0` is the only off switch): ultrathink asks Jev (`https://openrouter.ai/api/alpha/decisions` or the Vercel AI Gateway, model `~typesafe/jev-latest` by default) one yes/no question at up to four points, always after the deterministic rules: `plan` skips planning for a message that is not new multi-step work (`Prompt Uplift · not planned: Jev judged this is not new multi-step work (<P>) · start with uplift: to plan it`; skill invocations such as `/gsd-*` and `uplift:` prompts never ask the plan gate); `ship` vetoes an LLM "done" on an untruncated patch in gate mode, or, with `ship.autoMerge` off, decides when there is no usable LLM verdict (`source: "jev"`), with `decision` in the `assess` JSON and a `- Jev:` line in the PR body, while the Greptile merge gate is unchanged; `knowledge` asks a knowledge-base-settled question after all when the cited document does not support the answer (after the clarifier's own questions, only while a question slot is free); `blocking` promotes a risky non-blocking question to blocking, never the reverse. New `decisions` config section (`enabled`, `model`, `points`, `timeoutMs`, `zdr`, `planSkipBelow`, `shipVetoAtOrBelow`, `shipApproveAt`, `groundedAt`, `blockingAt`), with zero-data-retention routing and `data_collection: "deny"` by default. Every failure fails open; each decision is recorded without state content or key (session record `decisions`, summary `Decisions · plan 0.97` or `Decisions · error (<kind>)`, one `ULTRATHINK_DEBUG=1` line), and `bin/ultrathink status` shows a `Decisions:` line. The endpoint is not configurable from config files; only `ULTRATHINK_DECISIONS_URL` in the environment changes it (see **Security**). See `docs/how-to/use-jev-decisions.md`.
- `openrouter` key-only credential provider: `ultrathink-mcp auth set-key openrouter --stdin` (or `--env-file <path> --var <NAME>`) stores the OpenRouter API key in the credential store (mode 0600); `OPENROUTER_API_KEY` is the fallback when no key is stored, and the stored key wins. `auth status` and `auth logout` handle it; `serve`, `check`, `auth login` and `scripts/mcp-register.ts` never treat it as an MCP server (`ultrathink-mcp: openrouter is an API-key provider, not an MCP server: …`, exit 2).
- `bin/ultrathink decisions check` (one live Jev decision: resolved model, latency, attempts, cost, ZDR and key source; exit 1 on failure with the error kind) and `bin/ultrathink decisions probe <plan|ship|knowledge|blocking> <cases.json>` (runs your own labelled cases through one point and prints P, the action under the current thresholds and agreement counts, for tuning).
- `ULTRATHINK_DECISIONS=0` turns every Jev decision point off for one process, whatever the config says: no request, no decision record, no plan-skip notice or `Decisions ·` segment. `bin/ultrathink status` shows `Decisions: off (ULTRATHINK_DECISIONS=0)`, and `bin/ultrathink decisions check` and `decisions probe` print `Decisions check: off (ULTRATHINK_DECISIONS=0)` or `Decisions probe: off (ULTRATHINK_DECISIONS=0)` and exit 1 without a request.
- Hindsight client (`src/hindsight/`) and `bin/ultrathink hindsight check [--roundtrip] [--json]` (opt-in, `hindsight.enabled`, default `false`). With it on, a URL (`hindsight.url` or `HINDSIGHT_API_URL`) and a key (the credential store, else `HINDSIGHT_API_KEY`, else `HINDSIGHT_API_TOKEN`; the stored key wins), ultrathink retains lesson text and sends the recall query. `ULTRATHINK_HINDSIGHT=0` turns it off. `bin/ultrathink status` shows a `Hindsight:` line and never the key. `--roundtrip` retains, recalls and deletes a probe in a throwaway `ultrathink-smoke-*` bank; it is a local check, not a hosted feature.
- RAGFlow client (`src/ragflow/`) and `bin/ultrathink ragflow check [--json] | datasets [--json] | search "<question>" [--dataset <id>]... [--limit N] [--json]` (opt-in, `ragflow.enabled`, default `false`). Grounding (`ragflow.ground`, default `false`) sends the grounding query and adds a "Documents (RAGFlow)" section to the plan as untrusted evidence, absent when grounding is off or the call fails. The key is the credential store, else `RAGFLOW_API_KEY`. The URL is `ragflow.url` or `RAGFLOW_URL`. `ULTRATHINK_RAGFLOW=0` turns it off. `bin/ultrathink status` shows a `RAGFlow:` line and never the key.
- `bin/ultrathink teach` (opt-in, `teach.enabled`, default `false`; capture defaults to `explicit`): `status`, `list`, `show`, `capture`, `recall`, `confirm`, `forget`, `sync`, `observe`, `promote` and `export --a2a`. Exit codes are 0 (ok), 1 (runtime failure, not ready, or unknown id) and 2 (usage or invalid input). `ULTRATHINK_TEACH=0` turns it off. `bin/ultrathink status` shows a `Teach:` line. A planned prompt can include a "Lessons from earlier work" section; it is absent when recall is off or the lookup fails.
- Hermes: with `teach.enabled`, the plugin registers `post_llm_call` (a detached `teach observe` when capture is `observe` or `auto`; `explicit` and off do not spawn) and `on_session_finalize` (a detached `teach sync`), the tools `ultrathink_lesson_save` and `ultrathink_lesson_recall`, and the commands `/ultrathink-learn` and `/ultrathink-lessons`. All fail open. The plan handoff stays short.
- Jev decisions: two more points, `teachable` and `skillworthy`, on the default list. Each sends a clipped lesson (name, description, body cut to 800 characters, kind, and occurrences for `skillworthy`) whenever that point is listed and a key exists. `bin/ultrathink decisions probe` accepts `teachable` and `skillworthy` as well as the earlier points. A project file cannot add either point.
- Muse planning engine: with the engine set to Muse, ultrathink runs the `muse` CLI headless (`muse exec --json`, one agent turn per call with the shell, file writes and web tools disabled) using your existing Muse login. New `muse` config section (`bin`, `model` default `"muse-spark-1.3-contributor"`, `reasoningEffort` default `"high"`, `callTimeoutMs`). The engine label is `muse:<model>`, or `muse:session default` when `muse.model` is `""`.
- Each host plans with its own engine: `think.engine` and the per-host `bin/ultrathink grok engine` control take `"auto"` (now the default), which resolves per host — Claude on Claude Code, Hermes and Omp, Grok on Grok Build, Muse on Muse Code. A named engine plans with one engine everywhere. Grok Build without a usable Grok login plans on Claude with a `(grok unavailable)` label instead of skipping the prompt. Teachable Moments are stored per host, so lessons never cross hosts whichever engine each one uses.
- Jev decisions: a Vercel AI Gateway rail alongside OpenRouter. New `decisions.provider` key (`"auto"` default, `"openrouter"`, `"vercel"`): `auto` uses Vercel when a Vercel key is present, else OpenRouter. New `vercel` key-only credential provider: `ultrathink-mcp auth set-key vercel --stdin` stores the Vercel AI Gateway key, with `AI_GATEWAY_API_KEY` as the fallback; the stored key wins. The Vercel rail calls the fixed `https://ai-gateway.vercel.sh/v4/ai/evaluation-model` with the model in the `ai-model-id` header (`typesafe-ai/jev` for the default alias) and sends only the state and questions — no provider preferences, session id or trace. `bin/ultrathink status` and `decisions check` show the rail (`provider vercel|openrouter`) and the key source, never the key. Vercel serves Jev only: engine selection and the Graph of Thought never reference it (proven by tests).
- Omp and Hermes plan with the session's active model: under `think.engine: "auto"` on those hosts, the engine follows the model in use (Hermes forwards its hook payload's model; Omp reads its session file's last `model_change` entry) instead of always using Claude. Unknown families and unreadable sessions keep the Claude default; an explicit `think.engine` still wins; a detected Grok without a login fails over to Claude, never skips.

### Changed

- `think.engine` now defaults to `"auto"` (each host plans with its own engine) instead of `"claude"`, and accepts `"muse"`. The per-host override is now `bin/ultrathink grok engine auto|claude|grok|muse`. To keep the old behaviour, set `"think": { "engine": "claude" }`.
- Hermes: the plan reaches the model as a short handoff (spec path, state file, Graph ID and kickoff instruction) instead of the full specification, because Hermes replays hook context in every turn and spills pieces over 10,000 characters to a file.
- `ultrathink-kickoff` fails open when Notion or Linear is down, unreachable, rate-limited or unauthorised: it creates no rows by hand, says which tracker failed in one line, and continues. The manual MCP fallback is only for when `track complete` itself cannot run. On Hermes it asks blocking questions with one `clarify` call (at most 5 questions of up to 4 choices, default first) and uses the defaults when no user is available.
- `ultrathink-sync` finds rows by Graph ID only (the Notion Task by the session record's `tracking.notion.taskUrl` or its `Graph ID`, the Linear issues by the session's tracking refs or the `ultrathink graph <id>` footer), never by branch, PR title or repo. It never creates rows, never clears `PR URL` or `PR #` in a turn without a pull request, fails open when Notion or Linear is down, unreachable, rate-limited or unauthorised (one line naming the tracker, no retries, the turn continues), and ends with `ultrathink-mcp session mark --state <file> synced`, which stops the Hermes end-of-turn nudge.
- The Agent Substrate brief is opt-in. ultrathink no longer requests a brief from a built-in local address; it asks only when `substrate.url` or `SUBSTRATE_URL` is set. The kickoff skill treats registering the graph with Agent Substrate as optional. To keep the old behaviour, set `substrate.url` (or `SUBSTRATE_URL`) to your Agent Substrate server's URL.
- Ship is opt-in: `ship.enabled`, `ship.autoMerge` and `ship.deleteBranch` now default to `false`. With the defaults, no skill run pushes, opens a PR or merges, and the plan, the end-of-run nudge and the ship skill only promise a merge when `ship.autoMerge` is on. `bin/ultrathink-ship` still works when run by hand, but `merge` refuses unless `ship.autoMerge` is `true`. To keep the old behaviour, set `"ship": { "enabled": true, "autoMerge": true, "deleteBranch": true }`.
- Grok `shunt` transport: `grok.shuntBaseUrl` and `grok.shuntModel` now default to `""`, and there is no built-in gateway. With `transport: "shunt"` and no `grok.shuntBaseUrl`, each engine call fails with an error naming that key; the prompt gets the conservative fallback spec and no rows are created. Claude is not used instead (`grok.fallbackToClaude` only applies to a missing Grok login). An empty `grok.shuntModel` sends `grok.model`. To keep the old behaviour, set `grok.shuntBaseUrl` to your gateway's URL and `grok.shuntModel` to the model name your gateway expects.
- `ultrathink-mcp auth login` no longer runs `tailscale` on its own. Over SSH the default is the loopback callback, with port-forwarding and paste-back instructions; a line mentions the Tailscale option. To keep the old behaviour, pass `--tailscale` or set `ULTRATHINK_OAUTH_TAILSCALE=1`.
- `scripts/mcp-register.ts` keeps a same-named `notion`, `linear` or `greptile` MCP entry that is not ultrathink's (its command does not end in `/bin/ultrathink-mcp`) and reports it as `kept`. ultrathink entries from another clone are still replaced, and entries that already match are reported `unchanged`. To keep the old behaviour of overwriting every same-named entry, pass `--replace`.
- `bin/ultrathink`, `bin/ultrathink-mcp` and `bin/ultrathink-ship` exit 127 with `ultrathink: bun not found. Install Bun 1.2 or later (https://bun.sh) or set BUN=/path/to/bun` when Bun is missing, and keep Bun's exit status when it cannot start. They used to exit 0. The hooks still exit 0, so a missing Bun never blocks a prompt. Scripts that relied on exit 0 should install Bun or set `BUN`.
- Grok Build state lives in `$GROK_PLUGIN_DATA/ultrathink`, else `${GROK_HOME:-~/.grok}/plugin-data/ultrathink`: `GROK_HOME` is now honoured by the engine, the Grok rule, the `ultrathink-plan` skill and `mcp-register` (`scripts/setup.ts` already honoured it). If you set `GROK_HOME` and want to keep your Grok control state, move `~/.grok/plugin-data/ultrathink` to `$GROK_HOME/plugin-data/ultrathink`.
- Grok Build users must re-run `bun scripts/setup.ts apply` after updating, so `${GROK_HOME:-~/.grok}/hooks/ultrathink.json` gets the new PR-sync matcher and the Grok rule gets the new state paths. The Grok plugin itself still needs `grok plugin enable ultrathink` once.
- `scripts/setup.ts`: the `CLAUDE.md` block says the plugin *can* track and applies only when tracking is configured; the Notion and Linear MCP servers are detected by exact name; the printed Hermes steps use `$HERMES_HOME` and say that the hook cap is a global Hermes setting of at least 105 s (600 recommended). Run `bun scripts/setup.ts apply` again to update an existing block.
- Missing-credential messages for Linear and Greptile name both routes: `ultrathink-mcp auth login <provider>` (OAuth) or `ultrathink-mcp auth set-key <provider> --stdin` (API key). Notion stays OAuth-only.
- Shipped text, hook matchers and examples carry no project-specific names: the tracking instructions give `Refs ENG-12` as the example identifier, and the PR-sync hook matches any MCP server's `create_pull_request`, `pull_request_create` or `createPullRequest` tool.
- Ship: a failed or timed-out Greptile review is re-triggered on the next `review` call (up to `ship.reviewRetries` per head commit) instead of blocking the ship after two failures on one commit. `review` output gains `passed`. To keep the old behaviour, set `ship.reviewRetries` to `1`.
- Ship: `ship.maxRounds` now counts only completed reviews below 5/5 or with open threads; failed and timed-out reviews never count.
- Ship: once the head's review passed (5/5, no open threads), `merge` keeps retrying until the PR merges: within each call up to `ship.waitMs` it retries pending CI, mergeability not computed, unreadable PR state or threads and transient GitHub errors, returning `waiting: true` and `next: "run merge again: …"` when the call's time runs out. Past `ship.mergeTimeoutMs` on one head commit, or on a terminal GitHub refusal (missing permission, requested changes, a closed PR; a branch-protection hold such as a missing approval is retried until the bound instead), the ship blocks and the PR comment lists the attempt history. Conflicts, failing CI, a moved head or a review below 5/5 go back to the agent (`next`), never merge. `run` merges within its own `ship.waitMs` budget when the review passed. The merge gate is unchanged.
- Ship: a PR merged outside the flow without a passing Greptile review of its head is reported blocked (`PR was merged outside the ship flow before its review passed`), never recorded as a ship merge.
- Jev decisions are always on: `decisions.enabled` is ignored in every file, and every listed point is consulted as soon as a key exists for the resolved rail. `ULTRATHINK_DECISIONS=0` is the only off switch. To keep the old behaviour (no Jev requests), set `ULTRATHINK_DECISIONS=0` in the host's environment, or remove the stored keys and unset `AI_GATEWAY_API_KEY` and `OPENROUTER_API_KEY`. The `Decisions:` status line and the `decisions check` line gain a `provider vercel|openrouter` segment, and the no-key message names both key routes.

### Fixed

- Notion rows are created with their properties again. The hosted Notion MCP now returns a data source's schema as JSON inside a text field, which the schema reader missed, so every Task, Issue and Sub-Issue row was created empty (no Item, Level or Graph ID) while tracking still reported complete, and lookups by Graph ID found nothing. The reader now parses the schema inside text payloads, and a schema read that misses the core names sends every property unfiltered, so a mismatch fails the create loudly instead of recording empty or partial rows.
- Hermes: plans are no longer dropped by Hermes' plugin hook cap. The planner reads the cap Hermes enforces and stops at `min(540, cap − 15)` seconds; below a 105 s cap (a deadline under 90 s) it doesn't start Bun and logs one warning naming `hermes config set plugins.hook_callback_timeout 600`. Nothing sets the cap for you: Hermes defaults to 30 s, so run that command yourself (at least 105 s, 600 recommended; it is a global Hermes setting that applies to every plugin). `scripts/setup.ts apply` prints the command but does not run it. On the deadline the plugin kills Bun's whole process group, so no engine call outlives the hook.
- Hermes: the prompt hook no longer creates Notion or Linear rows. `ultrathink-kickoff` creates them with `ultrathink-mcp track complete --state <file>`, so a plan that Hermes abandons can't leave orphan rows.
- A prompt that references an existing ultrathink graph (`graph ut-<id>-<8 hex>`, as dispatched workers and Linear issue footers do) is no longer planned again as a new graph on any host. Prefix it with `uplift:` to force a plan. On Hermes a bare skill preamble with no task is skipped too.
- Muse: the planning hook no longer recurses into itself. `muse exec` runs hooks with a sanitized environment, so the child marker never reached nested hooks and every nested plan re-planned; engine prompts now carry a sentinel that nested hooks recognise and skip.
- A dead engine is loud instead of silent. The session record keeps the first engine error (redacted, one line, at most 500 characters) and the stages that fell back to boilerplate, and the context warns up front — naming the engine, the error or the degraded stages, and the fix — instead of presenting generic text as a terse real plan with tracker rows to come. Without a track plan, the tracking section says no rows will exist rather than telling kickoff to finish missing ones, and kickoff resolves clarifications from the record instead.
- Hermes and Omp: stateless skips (`raw:`, commands, already uplifted XML, graph references, trivial acknowledgements) run before an engine is selected, and the Hermes plugin skips prompts that start with `/` and already uplifted XML before starting Bun.
- Hermes integration: the handoff's human-in-the-loop step asks blocking questions with one `clarify` call (at most 5 questions of up to 4 choices, recommended default first) instead of the nonexistent `AskUserQuestion`, and names Hermes' `todo` and `delegate_task` tools. With `/ultrathink-skip` armed, a trivial or bare-preamble prompt on Hermes and Omp now uses up the skip, as on the other hosts. The plugin strips a shared-session `[Name] ` sender tag that names the current sender before its skips and plans the untagged text (a `[label]` the user typed stays), and takes the planner's working directory from `TERMINAL_CWD` before its own. An armed skip is consumed before engine selection, so an unavailable engine cannot leave it armed. A PR a `delegate_task` subagent really opened (its own `gh pr create`, matched to the parent through `subagent_start`) nudges the parent; a delegate result that only cites a PR does not. Both sync nudges pass `graphId=`, and `ultrathink-sync` prefers it over a state file that a newer plan has since replaced. The ship skill loads `ultrathink:ultrathink-sync` by its Hermes name, and the plan skill falls back to `~/.hermes/ultrathink` when `HERMES_HOME` is unset.
- Notion rows whose create reply links to `https://app.notion.com/…` are counted as created.
- PR sync: tool names count as PR creation only when they end in the create verb, so `create_pull_request_review` and `create_pull_request_with_copilot` no longer link tracked rows to an unrelated pull request.
- `scripts/setup.ts` works from a clone whose path has spaces or non-ASCII characters, no longer counts lookalike MCP server names (such as `notion-foo`) as installed, removes its `ultrathink-setup-state.json` on `rollback`, and prints (without running) the Claude Code plugin uninstall commands.
- `scripts/mcp-register.ts` no longer rewrites Muse's entries on every run when only key order or a default `type: "stdio"` differs, verifies each removal, and backs up the `config.toml` under `GROK_HOME`.
- `scripts/mcp-register.ts` reads and backs up the `config.yaml` of the active Hermes profile (`<Hermes home>/profiles/<name>/config.yaml` when a profile other than `default` is active, or when `HERMES_HOME` points at a profile directory) instead of always the root `config.yaml`. When the active profile cannot be resolved, it backs up nothing and says so.
- `scripts/setup.ts apply` keeps the MCP servers recorded as added by earlier runs, so `rollback` still removes them after a re-run. `rollback` keeps its state file when a removal fails, prints the error and the manual `claude mcp remove` command, and retries on the next run.
- `scripts/setup.ts rollback` never removes a Notion or Linear MCP server you replaced after `apply` added it (for example with the gateway through `mcp-register --replace`): it removes a server only while `claude mcp get` still shows setup's user-scope HTTP entry with the hosted URL, reports a replaced one as left in place and a missing one as already removed.
- `scripts/mcp-register.ts` decides ownership from the user-scope entry only, the scope it adds to and removes from: a same-named project- or local-scope entry in Claude Code or Grok no longer blocks registration and is never touched.
- The `/ultrathink-off`, `-on`, `-skip`, `-status` and `-track` command files work when `CLAUDE_PLUGIN_ROOT` is not set: the model asks you for the ultrathink directory and runs `bin/ultrathink` from there, instead of failing.
- Ship: the done assessment is no longer blind after `gsd-autonomous` archives a milestone. When `.planning/phases` has no `*-VERIFICATION.md`, the latest `.planning/milestones/<version>-phases/*/*-VERIFICATION.md` statuses must all be `passed` (each other status is a gap; a phase without a readable verification counts as `missing`, and no verifications at all is a gap), and the milestone's audit status and scores go to the judge as evidence, instead of the judge seeing "0/0 phases, verification none".

### Security

- The Grok `cli` transport runs the `grok` process in a private per-process temporary directory (mode 0700) instead of a fixed, shared directory under the system temp directory.
- When `CLAUDE_PLUGIN_ROOT` is not set, the command files tell the model not to search for or run any other `bin/ultrathink`; it runs only the one in the directory you name.
- With no configuration, ultrathink no longer contacts an Agent Substrate server, runs `tailscale`, or pushes, opens pull requests or merges; each needs an explicit opt-in (see **Changed**).
- Jev decisions: `ULTRATHINK_DECISIONS_URL` is accepted only as an `https://openrouter.ai/…` URL or an `http://` or `https://` URL on `localhost`, `127.0.0.1` or `[::1]`, never with a user name or password in it. Any other value is ignored and the default endpoint is used; the `Decisions:` status line and `decisions check` then end with ` · ULTRATHINK_DECISIONS_URL ignored (must be https://openrouter.ai/… or a loopback URL)`. Only the URL's origin and path are used and printed. The Decisions client never follows a redirect, so the OpenRouter key cannot be forwarded to another host.
- Jev decisions: a project file (`<project>/.claude/ultrathink.json`) can only tighten consent: `decisions.zdr` only from `false` to `true`, and `decisions.points` is intersected with the list from the user files (`decisions.enabled` is ignored in every file). A repository sends nothing anywhere unless you stored or set a key, and it cannot turn zero data retention off. The two user files merge these keys as usual.
- Ship: in gate mode with `ship.autoMerge: true`, a Jev verdict never stands in for a missing or unusable LLM judge verdict: the result is `no judge available` or `assessment unavailable: …` exactly as without Jev, and the Jev decision is recorded with the action `none`. Jev can still veto a usable "done".
- `bin/run-bun` passes `--no-env-file` to Bun, so on Bun 1.3.3 and later the `.env*` files of the repository you work in are no longer loaded into ultrathink's hooks and CLIs, where they could set `OPENROUTER_API_KEY`, `ULTRATHINK_DECISIONS_URL` or any other variable ultrathink reads. Bun 1.2.x ignores the flag and still loads them.
- Lesson text is redacted (`src/teach/redact.ts`) before it is stored or leaves the machine. A project file (`<project>/.claude/ultrathink.json`) cannot opt you into Hindsight, RAGFlow or Teachable Moments: `hindsight.enabled`, `ragflow.enabled`, `ragflow.ground` and `teach.enabled` can only be turned off there (`teach.capture` can only be lowered). Jev decisions are always on but send nothing without your key, and there `decisions.points` can only drop points.

- `ultrathink-mcp notion init --parent <page>` creates the Agent Task Graph database in your Notion workspace; `--write-config` saves it to your config.
- Host-neutral config file `~/.config/ultrathink/config.json` (under `$XDG_CONFIG_HOME` when that is set). `~/.claude/ultrathink.json` and `<project>/.claude/ultrathink.json` still apply on top of it.
- Muse, Hermes Agent and Omp hosts, with one MCP gateway (`bin/ultrathink-mcp`) that serves Notion, Linear and Greptile to every host from a single credential store. Omp also gets a live status bar and plan cards.

### Changed

- Notion and Linear targets no longer default to the author's workspace. Set `notion.dataSourceUrl` and/or `linear.team` (or run `ultrathink-mcp notion init`); with neither set, tracking is off.
- The MCP gateway reports an upstream rate limit as a rate limit, with the retry delay when it is known, instead of as an authentication error.

### Fixed

- Ship: a passing review whose pull request is only waiting on CI, mergeability or conflicts is no longer counted as a failed round, so it cannot block the ship at `maxRounds`, and `review` now says what to wait for instead of "fix the listed findings".
- Ship: a transient Greptile tool or network error during a PR-mode review is reported as `pending` and retried on the next call, instead of being recorded as a failed round that counts toward `maxRounds`.

### Security

- Nothing notable in this release.
